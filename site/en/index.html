How it works

From question to Apply,
with PoB in the loop.

A short flow on the outside, multiple safety barriers on the inside.

  1. 01

    You ask

    “How can I improve?”, “why is my DPS low?”, or request a specific change.

  2. 02

    The bridge selects the context

    It sends the build core and adds gems, uniques, tree, or config only when useful.

  3. 03

    AI proposes typed actions

    The response can include a structured batch using any of the 18 actions known to the application.

  4. 04

    PoB simulates in isolation

    It validates the batch in a clone, performs a full rebuild, and measures the actual before and after.

  5. 05

    You review and decide

    The diff appears first. Only an explicit Apply changes the open build.

Security and privacy

Your key does not come with the app.
And it is not included in the build.

You choose the OpenAI-compatible provider. The key stays in local configuration and is used only in the authorization header of the HTTPS request.

Read the security documentation
  • Local API key

    Masked field; file excluded from Git and releases.

  • HTTPS required

    The key is sent only to the endpoint you configure.

  • No hidden proxy

    No telemetry, analytics, or intermediary service in V1.

  • Audited artifact

    Package published without configs, logs, saved builds, or credentials.

Transparency:

The provider receives your question, limited history, and the build context required to answer it. Use a provider whose retention policy you trust.
